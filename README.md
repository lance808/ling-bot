# Ling-bot

Ling-bot 是面向 Windows 的 QQ 机器人桌面端。它通过 SnowLuma 提供的 OneBot v11 WebSocket 接收和发送 QQ 消息，直接连接 OpenAI 兼容模型接口，并提供会话查看、人格与角色设置、工具权限、用量和日志界面。

日常 QQ 对话不依赖 DeepSeek Harness（DSH）。需要从 QQ 审批或指挥 DSH 时，可以单独启用内置桥接插件。

## 项目结构与已实现功能

```text
QQ 客户端 ←→ SnowLuma / OneBot v11 ←→ Node.js 后端 ←→ 模型服务
                                       ├─ stdio JSON-RPC ←→ Tauri 2 / WebView2 界面
                                       └─ 可选本地 HTTP 桥 ←→ DSH 侧插件
```

Tauri 负责窗口、托盘、单实例和后端进程管理；Node 后端负责连接、消息、模型调用与权限判定。Ling-bot 自身不实现 QQ 注入，QQ 接入由单独安装的 SnowLuma 完成。

| 功能 | 当前实现 |
| --- | --- |
| 模型连接 | DeepSeek、OpenAI、Moonshot、硅基流动的地址预设，以及自定义 OpenAI 兼容地址；实际请求以保存的地址为准。 |
| 模型选择 | 请求服务商的 `GET /models`，从返回目录选择模型；目录读取失败、为空或缺少目标模型时，可以手输模型 ID。不会用内置模型目录冒充上游结果。 |
| 连接与能力测试 | “测试连接”发送真实文本对话请求；“探测模型”只测试读图（视觉）能力，区分支持、不支持和未得到结论。生图能力不在聊天模型页探测：其模型、API 地址、Key 与前置审批都在「插件设置 → 独立文生图」配置。 |
| 对话 | 流式内容在桌面端展示，完成后发到 QQ；支持中止回合和多轮工具调用。私聊、群内 @、叫名字及配置的关键词可触发回复。 |
| 分条发送 | 一次回复可以拆成少量气泡逐条发出，像真人分几句说。边界由模型用结构化消息列表给出（`ling-msgs` 围栏块），解析器可校验：没写、写坏、超过条数上限都整条原样发，不猜、不丢内容。不按逗号/句号/换行机械拆，代码块、表格、列表整块保留。每条各过一次发送闸门（白名单/审计/限流），同一会话严格按顺序发，不同回合不交错；中止停在消息边界；历史只记真正发出去的内容。条数与间隔在「语言 → 分条」配置。 |
| 主动参与 | 群消息到来时按概率判断是否接话，并检查近期活跃、发言间隔与频率；主动回合用量单独统计。默认开启，可在配置中关闭。 |
| 触发判定 | 强触发（@ / 点名 / 私聊 / 指定群友）排队等当前回合结束；弱触发（关键词 / 提问 / 拍一拍 / 概率）丢弃并记一行，不为它插队。提问判定刻意保守，普通陈述句不触发。 |
| 人格与角色 | 两套独立卡片，支持新建、修改、复制、删除和切换；可设全局默认，或绑定某个群、某个私聊。内置行为规范只读。 |
| 会话 | 群聊、私聊分组查看收到的消息；每条消息有本地**楼层号**，可向上加载更早的历史、跳到未读、一键标记已读，未读有徽标。手动发送文本或本机图片、视频、语音、文件，单文件上限 100 MB。媒体实际投递能力取决于 SnowLuma 和 QQ。 |
| 会话楼层 | 每条消息分配单调递增的楼层号，记录“读到第几楼”。只有真的喂给过模型、或已被缓冲淘汰的楼层才算可达，避免重复回复或静默漏答。会话与已读位置跨重启保留。 |
| 日记 | 跨过零点后生成前一天的经历总结；启动时读回已有日记，缺失且当天有活动则补生成。模型不可用时降级为原始摘录而不是留空。 |
| 日记淡忘 | 每篇日记有权重，默认 100、每个自然日 -1；可手动锁定豁免衰减（解锁后从当天重新计算，不补算锁定期）。权重低于阈值不再进入上下文。 |
| 唤醒设置 | 被 @、被叫名字、被提问、被拍一拍、指定群友发言、关键词各自独立开关；另有每分钟/每小时唤醒次数硬限、多条消息合并窗口与两次主动发言的最小间隔。入口是「语言 → 唤醒」。 |
| 静音 | 四种方式让它闭嘴：全局开关、按会话静音、按时间段自动静默（支持 23:00–08:00 跨午夜）、聊天里发「闭嘴 30」「闭嘴 2h」临时静音，「说话」立刻恢复。静音期间 @ 与私聊也不回复。入口是「语言 → 静音」。 |
| 记忆 | 三块：**情境知识**（各会话近况与主动发言计数）、**日记与淡忘**（跨日生成，权重每天 -1，可锁定豁免）、**人格卡**（跨会话的记忆载体）。 |
| 工具调用 | 运行时注册表的全部工具，逐个标出风险等级、对哪些来源开放、要不要人工确认。插件启用/停用后自动反映，不用重启。 |
| 插件 | 从用户数据目录加载显式启用的插件；提供启停与加载状态。随包内置 `dsh-bridge`，另有 `echo` 示例。 |
| DSH 桥接 | 转发审批与提问、接收管理员私聊指令、查看待审批项，并将 DSH 回复送回管理员私聊。需要 DSH 侧兼容插件。 |
| 独立文生图 | 可选 `image-generation` 插件：独立API/Key/模型，AI立即取得taskId，管理员私聊引用前置审批后后台生成、统一媒体队列投递；重启不重放可能计费请求，投递失败仅重投保存图片。[配置与状态流程](docs/image-generation.md)。 |
| 联网搜索 | 三态：关闭 / 独立搜索 API / 服务商原生联网（智谱 GLM、OpenAI）。原生联网只在模型请求里声明，检索由服务商完成；证据只认结构化引用或协议角标。[使用说明](docs/web-search.md)、[逐服务商协议](docs/provider-native-search.md)。 |
| 运行观察 | 连接状态、环境体检、用量查询、工具调用记录、日志，以及上游返回的 reasoning 内容展示、按日归档和导出。 |
| 桌面操作 | 托盘显示窗口、重连 QQ、重启后端、退出；后端异常退出后有限次退避重启。关闭窗口只隐藏到托盘。 |

聊天模型页只探测读图，不探测生图：自动读图按视觉配置启用，聊天模型页的「探测模型」也只测读图（视觉）。文生图使用独立插件的 API 配置与前置审批——生图模型、地址和 Key 全部在该插件页填写，聊天模型页既不展示也不推断。手动发送媒体与聊天模型能力探测仍是独立功能。好友与加群请求目前只记录，不自动同意；也没有完整的群管理、Qzone 或语音识别/合成功能。

## 运行前提

- **Windows x64**：当前桌面运行与打包流程以此为目标。其他平台的下载选项不代表完整桌面支持。
- **Node.js 24.22.x**：项目基线见 [.nvmrc](.nvmrc)，[package.json](package.json) 和版本校验接受 `>=24.22.0 <25`。源码运行和构建时先执行 `npm run verify:node`；便携分发目录会带上打包时正在使用的 Node。
- **Microsoft Edge WebView2 Runtime**：桌面界面依赖系统 WebView2。没有时从 [Microsoft 官方页面](https://developer.microsoft.com/microsoft-edge/webview2/)安装 Evergreen Runtime。
- **QQ 与 SnowLuma**：需要真实收发 QQ 时另行安装和配置。请使用 SnowLuma 支持的 QQ 版本，并按其说明完成登录、注入和 OneBot 启用。
- **模型服务与 API Key**：需要可访问的 OpenAI 兼容 Chat Completions 接口。各服务对 SSE、工具调用、模型目录和图片输入的支持并不完全相同。

编译桌面壳还需要 [Rust MSVC 工具链](https://www.rust-lang.org/tools/install)和带“使用 C++ 的桌面开发”组件的 [Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)。具体 Windows 构建依赖可参考 [Tauri 官方前提说明](https://v2.tauri.app/start/prerequisites/)。仅运行已经构建好的 exe 不需要 Rust。

## 选择启动方式

| 方式 | 操作 | 需要什么 |
| --- | --- | --- |
| 仓库根目录 exe | 双击 [Ling-bot.exe](Ling-bot.exe) | 保留完整仓库目录，安装 Node 和 WebView2；不用现场编译 Rust。 |
| 开发启动 | `npm start`，或 `npm run dev` | Node、Rust MSVC、C++ 构建工具和 WebView2；脚本先构建 debug 壳，再启动。 |
| 便携分发目录 | `npm run bundle:desktop` 后运行 `dist/Ling-bot/` 内的 exe | 构建机需要上述编译工具；目标机需要 WebView2，Ling-bot 后端使用随包 Node。 |
| 仅后端 | `npm run backend` | Node；不打开桌面窗口，供调试 stdio JSON-RPC 使用。 |

根目录 exe 只是桌面壳，不能单独拷走使用：后端来自仓库中的源码目录，Node 默认从 `PATH` 查找，也可用环境变量 `LING_NODE` 指定。它不会在启动时重新编译界面和 Rust 代码。修改源码后，开发时使用 `npm start`；要更新根目录 exe，执行 `npm run build:root-exe`。

在仓库根目录执行：

```powershell
npm run verify:node
npm install
npm start
```

当前 Node 后端没有 npm 第三方运行依赖；首次运行的数据目录和内置插件由程序初始化，`npm install` 本身不承担这项工作。

生成便携目录：

```powershell
npm run verify:node
npm run bundle:desktop
```

分发时复制整个 `dist/Ling-bot/`，保留 exe、源码、插件和 `runtime/` 等内容。该脚本目前**只组装免安装目录**，不会自动产出 NSIS 安装包；也不包含 QQ、SnowLuma 或 WebView2。它复制当前 Node 可执行文件，因此应在 Windows x64、符合基线的 Node 环境下打包。开发和便携脚本目前按默认的 `desktop/target/` 位置查找构建结果；设置自定义 `CARGO_TARGET_DIR` 可能导致找不到产物。

“便携”指应用文件可整体移动，用户数据仍写入系统应用数据目录，不随 exe 放置。

## 首次配置

### 1. 接通模型

打开“模型设置”，依次完成：

1. 选择提供商或“自定义第三方”，填写并保存接口地址。常见形式为服务商域名或以 `/v1` 结尾的 API 地址；客户端会补齐 `/chat/completions` 与 `/models`。
2. 输入 API Key，点击“保存 Key”。
3. 点击“读取模型列表”，选择目标模型；服务商不提供目录或目录为空时，手输其文档中确认可用的模型 ID。
4. 点击“用这个模型”保存，再点击“测试连接”，确认当前地址、Key 和模型能完成文本对话。
5. 如需了解读图（视觉）能力，再点“探测模型”；聊天模型页只测读图，不测生图。测试连接和读图探测都会发真实请求，可能计费；读图探测成功只说明模型接受图片输入，不替代文本连接测试。生图能力与模型请在「插件设置 → 独立文生图」配置。

更换地址、Key 或模型后需要重新验证。“未测”与“不支持”不同；目录为空时应检查服务商的令牌分组、模型权限和接口地址，也可继续手填模型。

API Key 的读取优先级为：`LING_LLM_KEY` 环境变量 → DPAPI 保险箱 → 旧配置中的明文 `llm.apiKey`。通过界面保存时，Key 加密写入用户数据目录下的 `secret.vault`，同时清除配置中的旧明文 Key。环境变量存在时仍优先使用环境变量，界面清除本地 Key 不会移除启动环境里的值。

保险箱使用 Windows DPAPI `CurrentUser`，依赖 Windows PowerShell；无法使用 DPAPI 时，界面保存会报错，不会自动改存明文。换账户或迁移到另一台机器后通常需要重新填写 Key。DPAPI 不能防止以同一 Windows 账户运行的恶意程序。OneBot 和 DSH 令牌目前保存在配置中，**不属于 API Key 保险箱的加密范围**。

### 2. 接通 QQ / SnowLuma

1. 按 [SnowLuma 官方说明](https://github.com/SnowLuma/SnowLuma)安装并准备受支持的 QQ 客户端。
2. 概览的“环境体检”可检测 Node、QQ、SnowLuma，打开下载地址与本地控制台，并提供“QQ 启动”和“SnowLuma 启动”按钮。QQ 使用检测到的 `QQ.exe`；SnowLuma 在其目录执行 `node index.mjs`，优先使用该目录自带的 Node，否则使用 `LING_NODE` 或系统 Node。
3. 完成 QQ 登录与 SnowLuma 注入，在 SnowLuma 控制台启用 **OneBot v11 正向 WebSocket 服务端**。本项目作为客户端主动连接它，不是反向 WebSocket 接收端。
4. 在 Ling-bot 用户配置中填写 `onebot.wsUrl` 和对应 WebSocket 服务的 `accessToken`。默认地址为 `ws://127.0.0.1:3001`；HTTP 与 WebSocket 的令牌可能不同，应使用 `networks.wsServers` 对应项的值。
5. 重启后端，检查连接状态及 QQ 在线状态；在“安全”页添加需要参与的群和私聊白名单，再进行测试。

环境体检使用默认控制台与 OneBot 端口做 TCP 检测，端口开放只表示有服务监听，不能证明 QQ 已登录或 OneBot 鉴权正确。“SnowLuma 启动”返回成功仅表示启动进程已创建，仍需等待并检查实际连接。当前没有对应的 SnowLuma 停止按钮，也不会代替用户完成 QQ 登录。

便携包内的 Node 用于 Ling-bot 后端；启动 SnowLuma 时仍按上文规则寻找 Node。自动检测不到安装位置时，可在启动 Ling-bot 前设置 `LING_QQ_EXE`、`LING_SNOWLUMA_DIR`，或在配置中填写 `qqExe`、`snowlumaDir`。界面在未检测到 QQ 或已有手动指定路径时，也会显示 QQ 目录和 exe 选择入口。

### 3. 配置文件和参与范围

界面「配置」组按"先跑通什么"排列：

```
模型设置 → 人物设置 → 插件设置 → 视觉 → 语言 → 记忆 → 工具调用 → 系统安全
```

其中**《语言》页是三个分栏**：`唤醒`（什么消息值得起一个回合）、`分条`（一次回复拆成几个气泡）、`静音`（让它闭嘴）。三者是同一件事的三个侧面（该不该开口 / 开口怎么说 / 现在能不能说），所以共用一个入口。

桌面端（包括开发启动的桌面壳）使用 `%APPDATA%\ling-bot` 保存用户数据。首次尚无配置文件时使用默认值；界面保存设置后写入配置。需要手工配置 OneBot 时，先从托盘退出应用，将 [config.example.json](config.example.json) 复制到该数据目录，命名为 `config.json`，再填写；若已有配置，应修改现有文件，不要直接覆盖。**仓库根目录中的同名配置不是桌面端默认读取位置。**

仅后端运行默认使用当前工作目录下的 `data/`，可通过 `LING_USER_DATA` 指定数据根目录。完整默认配置与校验规则见 [schema.mjs](src/config/schema.mjs)，示例配置只列出常用项；未知字段会导致启动校验失败。

**白名单与管理员是两张表，回答两个不同的问题**：

| 配置 | 回答的问题 | 效果 |
| --- | --- | --- |
| `allow.groups` / `allow.private` | **谁能跟它说话**（准入） | 名单外的消息进不来 |
| `admin.qqIds` | **谁能让它动本机**（授权） | 管理员私聊可拿宿主机工具、可批准高风险操作 |
| `admin.inheritWhitelist` | 兼容开关 | 打开后 `allow.private` 也视为管理员 |

默认三者都为空：谁都不能对话、也没有管理员。**把某人加进白名单不会授予他管理员权限** —— 这是有意的，否则"允许聊天"会顺带给出本机操作权。升级前的版本把两者当成一张表；如果你的白名单里填的就是自己的号，可以在「安全」页打开「白名单视为管理员」保持原行为，或者直接把号填进管理员名单（推荐后者）。

默认 `allowAllWhenEmpty` 为 `false`，黑名单优先于白名单。DSH 管理员私聊可以作为审批通知的投递目标（发送闸门对"送得到"做了豁免），但仍受黑名单、出站过滤和限流约束；这份投递豁免**不参与授权**。

需要调整触发词、主动发言、发送限额或工具目录时，退出后编辑相应的 `llm.keywords`、`persona.name`、`proactive`、`limits` 和 `tools.roots`，再重启。`proactive.enabled` 默认是 `true`；不希望概率接话时设为 `false`。`tools.roots` 为空时，当前启动逻辑会使用系统临时目录中的专用工作区，并不开放整个磁盘。

### 分条发送

一次回复可以拆成少量气泡逐条发出，像真人分几句说（界面入口：**语言 → 分条**）。边界**不是**按标点或换行推断的，而是模型显式写出来的结构化消息列表：

````text
```ling-msgs
["第一条完整的话", "第二条完整的话"]
```
````

解析器对它有硬校验：恰好一个 `ling-msgs` 围栏、内容是合法 JSON、顶层是数组、元素全是字符串。任何一条不过就**整条原样发出** —— 不改写、不猜测、不丢内容。普通代码块（``` 和 ~~~ 不带 `ling-msgs`）、表格、列表永远不会被切开；如果模型把一段代码拆到两条里，会按围栏状态自动合回一条。

`reply` 三项配置（界面「语言 → 分条」，也可写进 `config.json`）：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `reply.splitEnabled` | `true` | 硬开关。关掉之后即使模型写了分条块也整条发出。 |
| `reply.maxMessages` | `3` | 单次最多几条，允许 1–10（1 = 始终整条发）。超过上限的内容并进最后一条，不丢。 |
| `reply.intervalMs` | `800` | 相邻两条间隔，允许 100–10000 毫秒。 |

三条边界值得记住：

1. **每条各过一次发送闸门** —— 白名单、出站审计、限流对每一条单独生效，不是"整段检查一次、然后拆开发"。
2. **同一会话严格按顺序** —— 两个回合几乎同时结束时，后来的排队等前一个发完，不会出现 A1 B1 A2 B2。中止停在消息边界：点停止后不再冒出新的一条，已发出的不撤回。
3. **历史只记真正发出去的** —— 被限流挡下的那条不进上下文，否则下一轮它会以为自己说过；一次回复只算一个主动回合，不是三条。

启停不需要重启；后端启动时会严格校验这三项（写错直接 E40XX 起不来，而不是静默夹到合法值）。

### 视觉

QQ 里发的图片可以真的让模型看到（`[图片]` 不再只是一个占位符）。**默认关闭**，在界面「视觉」页打开。

开关状态与「模型能不能读图」是**两件独立的事**，界面分成两块显示：

- **开关**（`vision.enabled`）—— 你想不想让它带图；
- **读图能力探测** —— 「探测模型」只测读图，实测结论三态：支持 / 不支持 / **未探测**。

「未探测」绝不会显示成「不支持」。这是有意分开的：探测是一次独立的小请求，它成功只说明模型**接受**图片输入；真实回合能不能读到图，还取决于开关、取图是否成功、有没有超预算。两件事都通了才算真的读图，所以「探测可用」不等于「聊天里已经读过图」。

关闭之后不是"界面不显示图片"，而是**真的停止取图与提交**：不再调用网关 `get_image`、不再抓 URL，请求体里也没有 `image_url`。消息文本里仍是 `[图片]`，并附一句"你看不到图里的内容，不要猜"——否则模型要么编造，要么突兀地说自己看不见。

图片预算（每回合，界面显示的是夹取后实际生效的值）：

| 字段 | 默认 | 硬上限 | 说明 |
| --- | --- | --- | --- |
| `vision.maxImagesPerTurn` | `3` | 4 | 本轮消息最多几张 |
| `vision.maxHistoryImages` | `2` | 3 | 历史/引用最多几张 |
| `vision.maxBytes` | 4 MB | 4 MB | 单张字节上限 |
| `vision.maxTotalBytes` | 8 MB | 8 MB | 一回合总字节 |
| `vision.maxPixels` | 36,000,000 | 同左 | 单张像素（防图片炸弹） |
| `vision.timeoutMs` | `8000` | 15000 | 单张取图总时限（含 DNS 与每一跳） |
| `vision.historyWindow` | `6` | 8 | 历史回看范围（楼） |
| `vision.includeQuoted` | `true` | — | 是否连引用的那条消息的图一起看 |
| `vision.cacheTtlMs` | `300000` | 300000 | 图片内存缓存有效期（不落盘） |

所以默认一回合最多 `3 + 2 = 5` 张、总字节不超过 8 MB。历史图**只提交一次**：提交过的楼层会被记住（含重启），下一回合不再重复提交——否则每轮都重新塞一遍旧图，成本按回合线性增长，而模型其实早就看过了。

图片元数据（文件标识、类型、字节、宽高、展示名）会随会话一起保存，**URL 和 base64 永远不落盘**：URL 带 QQ 的临时鉴权参数，base64 会让 `sessions.json` 涨到几 MB。重启后 URL 必然失效，这是预期行为，取图会退回网关缓存名；连缓存名也没了的那条消息会如实降级成"有图但取不到"。

取图本身有四类边界：只认 PNG/JPEG/GIF/WebP（按魔数，不看扩展名）、单张与单回合字节上限、像素上限、以及 URL/重定向/本地缓存路径的安全校验（拒绝私网与回环地址、逐跳校验重定向、本地路径必须在 SnowLuma 目录内）。任一张取不到只影响那一张，整回合降级成纯文本继续，并给出分类原因（`E3101`–`E3109`），不会笼统记成"模型不支持"。

完整的实现说明、安全边界与降级矩阵见 [docs/vision.md](docs/vision.md)，接口契约见 [docs/vision-contract.md](docs/vision-contract.md)。

### 联网搜索

联网搜索有**三种互斥模式**：关闭、独立搜索 API、服务商原生联网。

| 模式 | 配置 | 谁检索 | 对哪些回合生效 | 用不用搜索服务商 Key |
| --- | --- | --- | --- | --- |
| 关闭 | `network.enabled = false` | 谁都不检索；Ling-bot 不发声明也不发搜索请求 | 全部 | 不用 |
| 独立搜索 API | `network.enabled = true` + `network.mode = "api"` | Ling-bot 自己调搜索服务商 | 只有管理员私聊与桌面控制台（工具是 `needs: host`） | 用 |
| 服务商原生联网 | `network.enabled = true` + `network.mode = "native"` | 模型服务商在它自己的服务端检索；Ling-bot 只在请求体里声明 | **每一次模型请求**（含群聊、主动回合与工具循环） | 不用（用聊天模型 Key） |

默认配置下没有任何搜索工具，也没有原生联网声明：`network.enabled` 缺省 `true` 只是"允许"，`network.mode` 缺省 `api`，插件 `web-search` 铺盘但不启用，`network.native.provider` 缺省为空。不要把它理解成"默认就联网"。

**独立搜索 API**：模型在需要时调用 `web_search` 查网页，或调用 `web_fetch` 读某个公网页面的正文，回答里带出处。三条同时成立才有工具：

| 层 | 字段 | 默认 | 作用 |
| --- | --- | --- | --- |
| 总闸 | `network.enabled` | `true` | 关掉后不再发送任何联网声明/工具；独立搜索零请求，在途请求立即中止 |
| 插件 | `plugins.enabled` 含 `web-search` | 否 | 不启用时工具根本不会登记 |
| 配置 | 服务地址 + API Key | 空 | 缺 Key / 地址非法 / 服务类型不受支持时调用明确失败（`E4081`），不会伪装成"没搜到" |

本轮只实现 **Tavily Search API**（`POST {baseUrl}/search`，`Authorization: Bearer`）。`provider` 配成未知值会被明确拒绝（`E4081`），不会静默按 Tavily 发送。密钥只进本机加密保险箱（DPAPI），不回显、不进日志、不进快照；"Key 不下发"只限 `web-search` 由宿主托管的这一把，**不是其他插件的通用 secrets 规则**。

**服务商原生联网**：在《插件设置》页选中「联网搜索」插件，在插件列表与插件详情之间的「联网搜索（宿主级设置）」里选「服务商原生联网」，再选服务商（本轮只有智谱 GLM 与 OpenAI），设置条数（1–20，仅智谱用作 `count`）。协议只由显式选择的服务商决定，不按模型名猜；未选择或未适配的服务商不会发送任何联网参数。请求字段分别是：

- 智谱：`tools:[{type:"web_search", web_search:{enable:true, search_result:true, count:N}}]`，走现有 Chat Completions，追加且不覆盖插件工具；
- OpenAI：`web_search_options:{search_context_size:"medium"}`，走现有 Chat Completions，不追加工具。

**证据只认协议里明确约定的东西**：结构化来源/引用（OpenAI `url_citation`、中转返回的智谱 `web_search[]`）或协议规定的正文角标（智谱 `[来源：ref_N]`）。HTTP 200、回答日期正确、模型自称"我联网查了"都不算证据。没有证据时状态是「无法确认」（`unknown`），不是成功；上游明确拒绝联网参数（`400/404/422` + 窄关键词）时标 `rejected`，并自动去掉联网参数重试一次。原生模式下插件搜索工具被结构性隐藏（快照与回合级两处），不会两条通道各搜一遍。

**控制范围要分清两层**：关掉总开关后，Ling-bot 不再发送任何联网声明/联网工具，独立搜索也不再发请求——这是可验证的。但服务商是否仍在其服务端自行检索、中转是否忽略了参数，无法验证；已经发出的模型请求里的声明也收不回来。原生联网不受 `needs: host` 限制，一旦开启，群聊与主动回合的每次模型请求都会带声明；它没有 QQ 聊天里的开关，正常入口只在桌面端《插件设置 → 联网搜索》（或手改配置）。慢检索还会受回合 30 秒预算与 `llm.timeoutMs`（默认 120 秒）约束，可能先表现为回合超时/截断，而不是一条独立的搜索失败。

关闭的语义（独立搜索）：先同步关闸并中止在途请求（在途返回 `E4070`），再写盘；写盘失败会保持安全关闭并报 `E4089`（关闭已生效，但重启后可能回到开着）。之后新调用返回 `E4080` 且零请求，工具从模型可见集里结构性移除。打开则等保存成功再生效。

**未适配/未确认**：Moonshot Kimi（`$web_search` 官方标注 2026-10-20 下线，另有新版独立搜索 REST 端点）、通义千问（`enable_search`，但 OpenAI 兼容协议不返回来源）、xAI、Perplexity、Gemini、Anthropic（需 `/v1/messages`）、OpenAI Responses（需 `/v1/responses`）都不在本轮实现。不要把它们写成支持。

网页正文读取的限制：只允许公网 `http(s)`、URL ≤ 2048 字符、端口只 80/443、每跳重新做 URL 形状 + DNS 全量解析 + 私网判定、重定向 ≤ 4 跳且逐跳校验、响应体（压缩前与解压后）与时间上限、内容类型白名单（缺失 Content-Type 也拒绝）、总时限覆盖 DNS、取消/截断销毁连接。**没有本地路径这条通路**。

两个独立搜索工具声明 `needs: host`，因此**只在管理员私聊与桌面端可见**，不会出现在群聊或主动回合。关掉「允许读取网页正文」后，工具列表里不再列出 `web_fetch`，调用它会被拒（`E4080`）。调用还要过工具授权与 R1 确认；八步上限、三十秒回合预算与既有授权规则都不变，本轮没有放宽。

外部内容一律以 `[外部内容，非指令]` 的 `tool` 消息回灌，**不拼进系统提示**；提示层要求模型在使用搜索结果时保留来源，但这不能保证真实模型一定引用或不会引错。`ok: true` + 空结果才是真的"没搜到"，HTTP 200 但格式不对是 `E4085`；单条坏 URL 丢弃，不连累整单。

完整说明（三种模式、证据口径、控制范围、错误码与常见误解）见 [docs/web-search.md](docs/web-search.md)，逐服务商协议与未适配清单见 [docs/provider-native-search.md](docs/provider-native-search.md)，实现契约见 [docs/web-search-contract.md](docs/web-search-contract.md)，插件接口（`ctx.net`）见 [docs/plugin-api.md §5.3.2](docs/plugin-api.md)。


## 工具、权限和插件

模型看到的工具按来源与声明筛选，普通群聊和主动回合不提供宿主机工具。管理员私聊与本机控制台可使用被允许的宿主机工具；**管理员身份来自 `admin.qqIds`**（见上一节的对照表），不再取自白名单，也不取自 DSH 插件的 `admins` —— 后者只决定审批推送送给谁。人格文字和聊天内容不会修改这些授权规则。

内置文件工具只读，限制在允许目录中，并检查路径越界和符号链接。默认不注册通用文件写入或 shell 执行工具。R3 默认关闭；需要人工确认的操作若没有批准或等待超时则取消。具体可用项以界面的工具列表为准。

### 人工确认怎么回答

R2/R3 工具调用需要人点头，确认卡会同时出现在桌面端确认条和**管理员私聊**里（群聊不会收到卡片：群里所有人都看得见，等于谁都能批）。

- **推荐：引用那条卡片回 1（同意）或 2（拒绝）** —— 引用是唯一精确的定位方式，并发多条时也不会批错对象。
- 不带引用时，只有当前会话里你名下**恰好一条**待确认才认；两条以上会要求你引用。
- 也可以用「同意 3」指定序号，或「拒绝 confirm-xxxx」指定请求。
- 一次确认只对一次调用有效，**没有"本会话内总是允许"**；超时 60 秒按拒绝处理。
- 桌面端和 QQ 端**只有先到的那次生效**，另一端会收到"已经处理过了"。

宿主确认与 DSH 审批是两套独立队列：引用宿主的卡片就由宿主处理，引用 DSH 的卡片就交给插件，互不接管。

### 插件

插件是磁盘上的独立包：每个插件一个目录，内含 `plugin.json`（声明）和入口文件（行为）。**新增、更新、修改配置、启用停用都不需要重新编译主程序**，把插件包放好后重启应用即可。

目录位置：

- 出厂插件源：[plugins/](plugins/)（随程序分发）
- 实际加载位置：**程序目录下的 `plugins/<插件 id>/`** —— 默认就和出厂源是同一层，不在 `%APPDATA%`
- 想放别处：设 `LING_PLUGINS_DIR` 指向任意目录
- 插件自己的运行数据：`plugin-data/<插件 id>/`（与代码、配置分开，仍在用户数据目录）

> 插件目录此前在 `%APPDATA%\ling-bot\plugins`，现已改到程序目录下。升级后启动时会**自动把旧目录里缺的插件补过来**（只补缺，不覆盖新位置已有的同名插件，也不删旧目录），所以旧插件不会凭空消失。

清单可声明：稳定的 id（必须等于目录名）、名称/版本/描述、兼容的接口版本（`apiVersion`，主版本须为 `1`）、配置项（类型/默认值/必填/校验，密码类字段自动加密存储）、工具（名称/用途/参数/可见范围/风险等级/**行为分类 `effects`**）、生命周期钩子（`init` / `callTool` / `testConnection` / `dispose`）。界面上的插件列表、配置表单、工具清单和诊断区**全部由清单驱动**，加插件不用改界面代码。

插件工具在**群聊 / 陌生人私聊 / 主动回合**里默认**完全不可见**，需要管理员在 `config.json` 的 `plugins.chatTools` 里点名（或写 `setting` 的 `plugins.chatTools.<档位>`）。三档互相独立：给群开了不等于给私聊开，**主动回合要单独开**。这是刻意的收紧——「能发图」「会花钱」的能力不该因为装上插件就自动交给群里每个人。

`effects` 让插件声明"我要做什么"（`chat.send` / `chat.send.media` / `paid` / `exec` …），宿主据此抬高**风险下限**：`effects: ["chat.send"]` 的工具即使写 `risk: "R0"` 也按 R1 处理。所以"发消息"和"收费生图"不能靠声明 R0 换取自动执行。被授权进聊天来源的工具在该来源下免逐次确认，但**收费工具永远逐次确认**。

插件执行时还能拿到两样受控能力（两种运行时一致）：**可信调用上下文 `ctx.caller`**（当前会话、触发者、来源、消息 id，由宿主生成，模型参数无法覆盖）和**受控聊天能力 `ctx.chat`**（读当前会话消息、发文本/媒体、引用）。`ctx.chat` **没有"目标会话"参数**——它永远只作用于当前会话，因此"读任意会话"在能力层面上就不可能。媒体用**句柄**传递，插件拿不到本机路径或 QQ 原始 URL；自己生成的文件只能从插件自己的 `dataDir` 登记。

三个边界值得记住：

1. **声明与行为分离。** 清单里不写执行逻辑，也不写 `origins` / `confirm` —— 可见范围与确认策略由宿主按 `needs`、`risk` 与 `effects` 推导，插件改不了。
2. **工具可见 ≠ 有权限。** 模型看到工具，只代表它在当前来源的候选集里；实际调用仍由宿主按来源判定，还要过 `plugins.chatTools`。
3. **只拦"按声明越权"，不是沙箱。** 默认 `process` 运行时把第三方插件放在独立子进程，超时或崩溃只杀子进程、主程序继续跑；而 `runtime: "in-process"` 的内置插件与后端同进程，没有强隔离。只装你信得过的插件。

格式细节见 [插件接口 v1](docs/plugin-api.md)，最小可运行示例见 [docs/plugin-template/](docs/plugin-template/)，随包示例见 [echo](plugins/echo/index.mjs)。

`stickers` 让模型看得懂 QQ 收藏里的表情、记住每张图的含义、按语境挑一张发送。

插件不会改你的人格文本。用法、边界与验收口径见 [docs/stickers.md](docs/stickers.md)。

`web-search` 让模型能查外网（`web_search`）或读一个公网页面的正文（`web_fetch`），回答里带出处。它默认不启用，而且**要三层同时成立**才会出现工具：总闸 `network.enabled` 开着、插件启用、插件配了服务地址与 API Key。本轮只实现 Tavily Search API 一个真实协议（不猜通用格式，未知服务类型明确报 `E4081`）；两个工具都是 `needs: host`，所以只在管理员私聊与桌面端可用，永远不进群；关掉「允许读取网页正文」后工具列表里不再有 `web_fetch`（硬调返回 `E4080`）。用法、限制与验收口径见 [docs/web-search.md](docs/web-search.md)。

## 可选：连接 DeepSeek Harness

普通 QQ 聊天无需此步骤。DSH 桥接默认关闭；随包 `dsh-bridge` 插件默认在启用列表中，但没配令牌时不会启动监听（也不会凭空占端口）。

1. 打开「插件」页 → 选中 `dsh-bridge` → 填监听端口（默认 `3458`，只绑 `127.0.0.1`）与管理员 QQ（逗号分隔），点「生成令牌」后保存。没配令牌时桥不会启动监听。
2. 需要从 QQ 下指令时填写目标 DSH 会话 ID。**获取方式**：在 DSH 左侧会话列表里找到目标会话，点会话右侧的「…」，选「复制会话 ID」，粘到「默认 DSH 会话」里。留空则只能处理审批与提问（`/dsh` 指令由 DSH 侧决定投给哪个会话）。
3. 在 DSH 侧另行安装兼容的 `dsh-qq-bridge` 插件，填入相同 `bridgeToken`、管理员列表，并按需启用 `relayApprovals`。该 DSH 侧插件不在本仓库内，Ling-bot 不会自动替你安装。
4. DSH 侧的 `bridgeUrl` 可以留空：Ling-bot 起桥后会写端口发现文件，DSH 侧自动跟上（DSH 比 Ling-bot 晚启动也能接上）。也可以显式填本地地址。保存后查看应用结果，若提示监听失败或需要重启，排查端口后重试或重启后端。

**审批是双通道的**：请求会同时出现在 DSH 桌面审批面板和 QQ 里，**哪边先回哪边生效**。桌面端先回时 QQ 那条会收到「已在桌面端处理」并作废；QQ 先回时桌面面板上迟到的点击会被丢弃。QQ 掉线不影响桌面审批（`onUnreachable` 默认交还 DSH）。协议细节见 [docs/dsh-bridge-protocol.md](docs/dsh-bridge-protocol.md)。

桥接只接管管理员的私聊消息，不接管群聊。可发送 `/dsh <指令>`、`待审批`，或引用某条审批/提问推送回复数字选项。并发有多条待回复时应引用目标推送，避免回答错对象。审批通知目前主要发给管理员列表中的第一位。

`免打扰 30分钟` 的实际语义是**在限定时段内自动同意审批**，不是单纯静音通知；使用前应理解它会放宽人工确认。DSH 发出的指令可能真的修改文件或执行命令，其执行权限仍取决于 DSH 侧配置。

## 验证与测试命令

在仓库根目录运行。测试规模会变化，以命令输出为准。

| 命令 | 用途与影响 |
| --- | --- |
| `npm run verify:node` | 校验当前 Node 基线。 |
| `npm test` | 运行 Node 单元测试。 |
| `node scripts/run-tests.mjs [过滤词]` | 逐文件汇总单测结果。在禁止创建子进程的环境里会明确标注 `EPERM` 并给出"逐个文件直接跑"的做法，而不是伪装成全仓失败。 |
| `npm run check` | 执行静态约束检查并运行测试；不是实际 QQ 投递或模型兼容性证明。 |
| `npm run smoke` | 启动临时数据目录中的后端，检查 JSON-RPC、快照和发送拒绝行为。 |
| `npm run e2e:plugins` | 插件骨架验收：装包→启用→调用→存配置→重启→停用→只改磁盘包加工具→坏插件隔离→授权边界。不连 QQ、不耗模型额度。 |
| `npm run e2e:plugin-host` | 插件宿主受控能力验收（**需要能创建子进程的普通终端**）：真实子进程下的 `ctx.caller`、`ctx.chat` 读/发/媒体句柄、跨会话引用拒绝、取消不杀进程。受限沙箱里会以 `EPERM` 提示退出。 |
| `npm run verify:course` | 课程表插件的**宿主级**验收：真实清单校验（含对象数组参数）、真实管理器启用、8 个工具登记、参数过滤后仍能拿到课程数组、授权默认关闭与点名后可用的对比。用临时目录，不碰真实数据。 |
| `node scripts/verify-web-search.mjs` | 联网搜索的**宿主级**验收：起一个本地模拟搜索服务，覆盖总闸（含在途中止）、工具可见性、结构化来源、空结果、鉴权/限流/协议不符/超时/上游故障、取消，以及网页读取的内网/本机/重定向/超大小/类型拒绝。**不读真实 Key、不发真实请求。** |
| `npm test -- test/course-schedule.test.mjs`（或 `node test/course-schedule.test.mjs`） | 课程表插件的**行为级**测试：录入保存、确认取消、周次/单双周、修改、重启恢复、数据隔离、冲突、损坏文件。 |
| `npm run e2e:llm` | 使用本地模拟 HTTP/SSE 上游验证解析和工具循环，不消耗模型服务额度。 |
| `npm run live -- <wsUrl> <wsToken>` | 连接真实 OneBot，读取登录/状态/列表并短时监听事件；不发 QQ 消息，输出可能包含账号、群与事件信息。 |
| `npm run live:llm` | 真实模型的流式对话、工具调用与中断检查；读取 `LING_LLM_BASE`、`LING_LLM_KEY`、可选的 `LING_LLM_MODEL`，会消耗额度。 |

[真实端到端脚本](scripts/e2e-real.mjs)会发送群消息并消耗模型额度，运行前应确认目标群和环境变量。API Key 由环境变量传给后端，不写入配置；OneBot WS 令牌写入临时配置，正常结束时清理。不要把真实令牌写进脚本、提交记录或公开的命令输出；命令行参数也可能被本机进程查看。

用户数据目录中主要包括 `config.json`（普通配置及连接令牌）、`secret.vault`（加密 API Key）、`persona.json`、`role.json`、`state/sessions.json`（会话楼层与已读位置）、`state/usage.jsonl`（用量账本）、`diary/`（按日日记）、`thinking/`（按日 reasoning 展示记录）、`logs/` 与 `plugin-data/`。**插件代码不在用户数据目录**，而在程序目录下的 `plugins/`（可用 `LING_PLUGINS_DIR` 覆盖）。复制便携目录或删除应用文件不会自动清除这些数据。

会话历史现在会落盘到 `state/sessions.json`：重启后消息列表、每个会话的楼层号与"读到第几楼"都会恢复。但它**不是 QQ 的历史备份**——每个会话只保留最近 200 条、会话数上限 500，更早的消息会被淘汰（被淘汰的楼层仍能正确推进已读位置，不会永久卡住）。日记是"有过更好"的记录，权重降到 0 后仍保留但默认折叠、不再进入上下文。用量与 reasoning 展示记录有各自的持久化逻辑；reasoning 只来自上游显式返回的字段，并受截断、保留时间和容量限制，不代表模型全部内部过程。

## 隐私过滤与当前限制

文本发送前会检查白/黑名单、发送频率及本机路径、凭据等特征；命中过滤时整条拒发，界面和日志提供拒因。日志有脱敏处理，工具结果也会被标记为外部数据。这些是基于规则的防护，可能误拦，也可能漏掉未匹配的敏感内容。

对话上下文及获准调用的工具结果会发往你配置的模型服务。手动媒体发送的过滤对象主要是文件名等描述，**不检查文件正文、图片内容或元数据**；发送文件前仍需自行检查内容。工具路径限制也不等同于覆盖全部敏感文件的保险箱。

仓库的 [.gitignore](.gitignore) 排除了常见配置、运行数据、保险箱和构建目录；它不能删除已经进入 Git 历史的内容，也不能替代提交前检查。日志、reasoning 导出与真实联调输出可能包含对话、账号或本机环境信息，分享前应人工检查。

目前还应留意：

- `onebot.followDiscoveredEndpoint` 已出现在配置中，但当前后端没有完整的 OneBot 端点自动发现接线；应明确配置 WebSocket 地址与令牌。
- 便携构建不是安装包构建，应用自身也不提供 QQ 或 SnowLuma 二进制。安装、版本适配和登录按各自官方说明处理。
- `/models`、工具调用、读图探测能否成功取决于服务商。用量缺失时部分统计使用估算；界面的 token 数不是账单承诺，也不涵盖所有独立探测请求。生图是否可用取决于独立插件页配置的端点与模型，与聊天模型的探测结论无关。
