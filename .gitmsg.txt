QQ 安装目录：改成三级识别 + 允许用户手动指定

这个项目要装到别人电脑上，原来那套识别对别人不好使。

原逻辑的毛病
------------
1. 写死 C/D/E/F 四个盘。装在 G 盘、F:\Apps\QQ 这类自定义目录就直接漏掉。
2. 注册表只从"卸载项"里捞 DisplayIcon，用 reg query /f QQ 全量搜。
   QQNT 新版很多机器上写的是别的位置，甚至不写 DisplayIcon。

现在的识别顺序（命中即停，且必须文件真实存在）
------------------------------------------------
1. Tencent\QQNT 的 Install 值 —— QQ 安装器自己写的安装目录。
   实测本机 HKLM\SOFTWARE\WOW6432Node\Tencent\QQNT 下
   Install = D:\QQ。不管装哪个盘、装到哪，走正常安装就写这个值，
   这是最权威的来源。
2. App Paths\QQ.exe —— Windows 按程序名定位 exe 的标准位置。
3. 卸载项的 DisplayIcon / InstallLocation —— 最后的注册表兜底。

再加一个手动入口
----------------
自动识别总有够不到的情况（绿色版、同时装新旧两版、注册表被清过）。
与其把识别逻辑堆到无限长去猜，不如让人自己指：

- 体检卡里加了「QQ 路径」一行：可直接填，也可点「选目录」或
  「选 QQ.exe」，回车即保存。右边标出这个路径是哪来的
  （手动指定 / 注册表识别 / 常见目录），自动找到的路径不对时
  用户一眼能看出来该改。
- 配置落到 config.qqExe。留空表示回到自动识别。
- 后端只校验形状（非空、长度、非法字符），不校验文件是否存在：
  用户可能想先填好、后装 QQ。存在与否由体检卡如实显示。

一个要紧的语义：手动指定必须最优先，且路径无效时不许静默
回退到自动识别。静默回退是最坏的行为 —— 用户填错了路径，界面
却显示"已安装"（其实用的是识别出的另一套），他以为自己填的生效了。
现在会如实报"你填的路径下没找到 QQ.exe"，并把原值带回界面。

顺带
----
- ling_pick_file 支持 kind="dir"（走 pick_folder），另加 "exe" 过滤器。
  用户脑子里记的是安装目录，不是 exe 完整路径。
- 启动 QQ 改用 cmd /c start "" "<exe>"，与 ling_open_url 一致。
  之前用 Command::spawn 配 creation_flags，QQ 起得来但不显示窗口，
  表现为"点了没反应"。交给 shell 拉起程序最省事也最可靠。
- 托盘退出：quitting 标志之前只写不读，CloseRequested 无条件
  prevent_close 把 app.exit(0) 拦住 —— 点退出毫无反应、进程还在。
  现在先判断再拦截，并加 I24 静态检查钉住"读写成对且判断早于拦截"。

测试：+7 条 JS（手动 exe / 手动目录 / 带引号 / 无效路径不回退 /
优先级 / 空串 / 后缀正确），全套 413 个用例通过。
